# NTBA0010: Static layout ErrorBoundary has limited interactive coverage

| Default severity | Code fix |
| --- | --- |
| Warning | No |

## Why it matters

In a Blazor Web App, a layout without an interactive render mode is static. Its `ErrorBoundary` covers only static SSR, so an exception thrown by an interactive event handler below the layout is not caught there unless the app's routes are globally interactive. Narrower boundaries around the page or widget that holds interactive content give more reliable containment.

## What is reported

- A layout component that uses a root `ErrorBoundary` while the app's routes are not globally interactive.
- The diagnostic is informational about coverage: the layout boundary does not protect interactive event failures in the content it wraps.

## How to fix

No automatic fix is offered, because the right boundary placement depends on the component hierarchy. Choose one:

- Move the `ErrorBoundary` into the page or widget that contains the interactive content:

```razor
@page "/orders"
@rendermode InteractiveServer

<ErrorBoundary>
    <OrderList />
</ErrorBoundary>
```

- Or, when broad layout recovery is intended, make the app's routes globally interactive by setting a render mode on `Routes` in `App.razor`, for example `<Routes @rendermode="InteractiveServer" />`, and keep the layout boundary.

## Configuration

None.

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0010.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0010
// layout component
#pragma warning restore NTBA0010
```
