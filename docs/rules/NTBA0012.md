# NTBA0012: Callback from outside the render flow should handle failures

| Default severity | Code fix |
| --- | --- |
| Warning | No |

## Why it matters

Timers, `NavigationManager.LocationChanged`, and events raised by application services call component code outside the renderer's call stack. An exception thrown there never reaches an `ErrorBoundary`. Depending on the source, it is lost, crashes the process (timer callbacks), or surfaces in unrelated code that raised the event. Handling the failure inside the callback and passing it to `DispatchExceptionAsync` returns it to Blazor's normal error handling.

## What is reported

In components with a declared interactive render mode, a callback with failure-prone work outside a catch that reports the exception, when it is:

- subscribed to `System.Timers.Timer.Elapsed`;
- passed as the callback of `new System.Threading.Timer(...)`;
- subscribed to `NavigationManager.LocationChanged`;
- subscribed to an event declared outside the `System` and `Microsoft` namespaces, such as an application notification service.

The callback can be a lambda or a method of the same component. Framework events raised from component event handlers, such as `EditContext.OnFieldChanged`, are not reported. Callbacks whose body is in another file are not analyzed.

## How to fix

Before:

```csharp
protected override void OnInitialized()
{
    _timer.Elapsed += OnElapsed;
}

private async void OnElapsed(object? sender, ElapsedEventArgs args)
{
    await Service.RefreshAsync();
    await InvokeAsync(StateHasChanged);
}
```

After:

```csharp
private async void OnElapsed(object? sender, ElapsedEventArgs args)
{
    try
    {
        await Service.RefreshAsync();
        await InvokeAsync(StateHasChanged);
    }
    catch (Exception exception)
    {
        await DispatchExceptionAsync(exception);
    }
}
```

## Configuration

`ntba.safe_types`, `ntba.failure_handling_methods`, `ntba.failure_prone_type_suffixes` and `ntba.failure_prone_method_prefixes` change which calls count as failure-prone. See [the rules index](README.md#analyzer-settings).

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0012.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0012
_timer.Elapsed += OnElapsed;
#pragma warning restore NTBA0012
```
