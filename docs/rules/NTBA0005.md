# NTBA0005: JS interop should use meaningful exception handling

| Default severity | Code fix |
| --- | --- |
| Warning | Yes: "Wrap body in try/catch and log" |

## Why it matters

JS interop can fail when the browser is not ready, when the JavaScript function throws, or when the circuit disconnects. An unhandled failure in an interactive method propagates into the circuit. Catching the failure where it happens and logging the exception object keeps the cause visible.

## What is reported

- A component method that performs JS interop (`IJSRuntime` calls) with no meaningful exception handling.
- Handling: a `catch` that does not throw contains the failure, unless it only catches cancellation (`OperationCanceledException`, `TaskCanceledException`, a `when` filter on `IsCancellationRequested`) or `JSDisconnectedException`. A `catch { throw; }`, or one that logs and rethrows, propagates the failure and does not count. Whether the catch logs is reported separately by NTBA0008, so a swallowed exception is reported once.
- JS cleanup that catches only `JSDisconnectedException` is accepted in `Dispose`/`DisposeAsync` and in `DisposeCore`/`DisposeAsyncCore` helpers when the JS call is directly inside the `try`, and in any `try` that disposes an `IJSObjectReference`.
- Built-in browser functions such as `confirm`, `alert`, `prompt` and `history.back` are not treated as failure-prone.
- Methods that only delegate to a safe local JS helper do not need their own wrapper.

## How to fix

Before:

```razor
@rendermode InteractiveServer

<button @onclick="HandleClick">Click</button>

@code {
    [Inject] private IJSRuntime JS { get; set; } = default!;

    private async Task HandleClick()
    {
        await JS.InvokeVoidAsync("doSomething");
    }
}
```

After:

```razor
@rendermode InteractiveServer
@using Microsoft.Extensions.Logging

<button @onclick="HandleClick">Click</button>

@code {
    [Inject] private IJSRuntime JS { get; set; } = default!;
    [Inject] private ILogger<ActionButton> Logger { get; set; } = default!;

    private async Task HandleClick()
    {
        try
        {
            await JS.InvokeVoidAsync("doSomething");
        }
        catch (Exception exception)
        {
            Logger.LogError(exception, "doSomething failed.");
        }
    }
}
```

## Configuration

- Strict mode does not change this rule's severity. No other settings apply.

See [Configuration](README.md#configuration) for the setting syntax.

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0005.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0005
// JS interop call
#pragma warning restore NTBA0005
```
