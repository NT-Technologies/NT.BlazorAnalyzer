# NTBA0003: Lifecycle method should use meaningful exception handling or owner ErrorBoundary coverage

| Default severity | Code fix |
| --- | --- |
| Warning | Yes: "Wrap body in try/catch and log" |

## Why it matters

Lifecycle methods such as `OnInitializedAsync` run during prerendering and circuit startup. An unhandled exception there can break the page or the circuit before the user can interact with it. Coverage has to come from an owner that renders the component inside an `ErrorBoundary`, because a component's own root `ErrorBoundary` does not protect its own lifecycle methods.

## What is reported

- Failure-prone work in `OnInitialized`, `OnInitializedAsync`, `OnParametersSet`, `OnParametersSetAsync`, `OnAfterRender`, `OnAfterRenderAsync`, or `SetParametersAsync` with no meaningful handling and no known owner `ErrorBoundary` coverage.
- Not reported when every known static owner path renders the component inside an `ErrorBoundary`. Coverage can flow through local `RenderTreeBuilder` helpers, protected concrete derived component usages, and `DynamicComponent` dialog hosts whose type slot sits inside a known `ErrorBoundary`.
- Custom boundary tags count only when the component type inherits `ErrorBoundaryBase`, including types from referenced assemblies.
- Pure delegation to a safe local helper is accepted. Trivial state mutation alone is not reported.
- Handling: a `catch` that does not throw contains the failure, unless it only catches cancellation (`OperationCanceledException`, `TaskCanceledException`, a `when` filter on `IsCancellationRequested`) or `JSDisconnectedException`. A `catch { throw; }`, or one that logs and rethrows, propagates the failure and does not count. Whether the catch logs is reported separately by NTBA0008, so a swallowed exception is reported once.
- Not failure-prone: calls returning a Result type (a `bool` property such as `IsSuccess`, `IsSuccessful`, `HasFailed` or `IsError`, directly or through `Task<T>`), `EventCallback` invocations, toast and snackbar services, and built-in browser functions such as `confirm` called through JS interop.
- Static SSR components are not reported: components with no declared render mode that have a `[CascadingParameter] HttpContext` property.

## How to fix

Before:

```razor
@rendermode InteractiveServer

@code {
    protected override async Task OnInitializedAsync()
    {
        await LoadAsync();
    }

    private async Task LoadAsync()
    {
        await Task.CompletedTask;
        throw new InvalidOperationException();
    }
}
```

After:

```razor
@rendermode InteractiveServer
@using Microsoft.Extensions.Logging

@code {
    [Inject] private ILogger<OrderPage> Logger { get; set; } = default!;

    protected override async Task OnInitializedAsync()
    {
        try
        {
            await LoadAsync();
        }
        catch (Exception exception)
        {
            Logger.LogError(exception, "OnInitializedAsync failed.");
        }
    }

    private async Task LoadAsync()
    {
        await Task.CompletedTask;
        throw new InvalidOperationException();
    }
}
```

The code fix offers this wrapping for `void` or `async Task`/`async ValueTask` methods. It is not offered when the component has an unrelated member named `Logger`. It reuses an existing `ILogger` field or property when one exists.

## Configuration

- Failure-prone detection: `ntba.failure_prone_type_suffixes`, `ntba.failure_prone_method_prefixes`, `ntba.safe_types`, and `ntba.failure_handling_methods`.
- `ntba.assume_owner_error_boundary = true`: suppresses this rule for component libraries whose consumers own the `ErrorBoundary`.
- Strict mode does not change this rule's severity.

See [Configuration](README.md#configuration) for the setting syntax.

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0003.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0003
// lifecycle method
#pragma warning restore NTBA0003
```
