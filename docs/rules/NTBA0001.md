# NTBA0001: Interactive render region should be protected by ErrorBoundary

| Default severity | Code fix |
| --- | --- |
| Info (Warning in strict mode) | No |

## Why it matters

An exception thrown from an event handler in an interactive component can terminate a Blazor Server circuit, which disconnects the user and discards their in-memory state. An `ErrorBoundary` above the component (or a component derived from it) contains the failure so the rest of the page keeps working. This rule reports each independently interactive region that has no such containment.

## What is reported

- Each uncovered, independently interactive, user-visible render region in an explicitly interactive component. One diagnostic is reported per region, at the region's source location when it can be mapped.
- Regions that count:
  - HTML event handler roots such as `@onclick`
  - component callback roots backed by `EventCallback`, delegates, method groups, lambdas, or anonymous methods (for example `<EditorForm OnSave="HandleSave" />`)
  - component binding roots such as `@bind-Value`
- Content that does not count by itself: inert HTML with no interactive attributes, plain `RenderFragment` or `RenderFragment<T>` content without callback or binding semantics, and `PageTitle` and `HeadContent`.
- A component that derives from `ErrorBoundary` is still reported when it renders an unprotected interactive region. The rule looks at rendered regions, not the base type.
- A region is covered when the component's own markup wraps it in a boundary, or when every component that renders this component does so inside a boundary, at any nesting depth. Any component deriving from `ErrorBoundaryBase` counts as a boundary, including custom boundaries from other packages.

## How to fix

Before:

```razor
@rendermode InteractiveServer

<button @onclick="IncrementCount">Click</button>
```

After:

```razor
@rendermode InteractiveServer

<ErrorBoundary>
    <button @onclick="IncrementCount">Click</button>
</ErrorBoundary>
```

Content inside an `ErrorBoundary` is not reported by NTBA0002 either, so the handler does not also need its own `try/catch`.

## Configuration

- `ntba.assume_owner_error_boundary = true`: for reusable component libraries whose consumers own the `ErrorBoundary`. Suppresses this rule, NTBA0002, and NTBA0003.
- Strict mode: `<NTBlazorAnalyzerMode>strict</NTBlazorAnalyzerMode>` in the consuming project raises the severity to Warning.

See [Configuration](README.md#configuration) for the setting syntax.

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0001.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0001
// interactive region
#pragma warning restore NTBA0001
```
