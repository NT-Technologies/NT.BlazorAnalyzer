# NTBA0011: Component task failure is never observed

| Default severity | Code fix |
| --- | --- |
| Warning | No |

## Why it matters

A task that a component starts but never awaits runs outside Blazor's error handling. If it fails, neither the renderer nor an `ErrorBoundary` sees the exception, so the failure disappears silently. `ComponentBase.DispatchExceptionAsync` exists to route exactly these failures back to the component, where the nearest `ErrorBoundary` can handle them.

## What is reported

In components with a declared interactive render mode:

- A discarded task: `_ = LoadAsync();`
- A task-returning call used as a statement in a non-async method or lambda, for example `_dialog.CloseAsync();` inside a `void` method. Async methods are left to the compiler's CS4014 warning.
- `ConfigureAwait(...)` on the task does not change the result.

The task is reported only when its work can fail without being handled:

- a call to a component method whose body has failure-prone work outside a catch that reports the exception;
- a delegate argument, such as `Task.Run(async () => await Service.LoadAsync())`, whose body has unhandled failure-prone work;
- any other awaitable call that is not on a known low-risk or configured safe type.

`_ = InvokeAsync(StateHasChanged)` and `_ = Task.Delay(...)` are not reported.

## How to fix

Await the task when the caller can be async:

```csharp
private async Task SelectAsync()
{
    await _dataGrid.RefreshDataGridAsync();
}
```

For intentional background work, catch failures inside the task and dispatch them:

```csharp
private void StartRotation() => _ = RotateBannersAsync();

private async Task RotateBannersAsync()
{
    try
    {
        while (await _timer.WaitForNextTickAsync())
        {
            await AdvanceBannerAsync();
        }
    }
    catch (Exception exception)
    {
        await DispatchExceptionAsync(exception);
    }
}
```

## Configuration

`ntba.safe_types`, `ntba.failure_handling_methods`, `ntba.failure_prone_type_suffixes` and `ntba.failure_prone_method_prefixes` change which calls count as failure-prone. See [the rules index](README.md#analyzer-settings).

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0011.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0011
_ = WarmCacheAsync();
#pragma warning restore NTBA0011
```
