# NTBA0007: Async component method should return Task

| Default severity | Code fix |
| --- | --- |
| Warning | Yes: "Change return type to `Task`" |

## Why it matters

An `async void` method gives its caller no `Task` to await. Exceptions from it are raised on the synchronization context instead of flowing back to the framework, so Blazor cannot observe completion or failure. Returning `Task` or `ValueTask` keeps exception flow and completion visible to the framework.

## What is reported

- An `async void` method in an interactive component.
- The code fix is offered only for eligible methods.

## How to fix

Before:

```razor
@rendermode InteractiveServer

<button @onclick="Save">Save</button>

@code {
    private async void Save()
    {
        await Repository.SaveAsync();
    }
}
```

After:

```razor
@rendermode InteractiveServer

<button @onclick="Save">Save</button>

@code {
    private async Task Save()
    {
        await Repository.SaveAsync();
    }
}
```

Event handlers such as `@onclick` accept a `Task`-returning method, so no markup change is needed.

## Configuration

None.

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0007.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0007
// async void method
#pragma warning restore NTBA0007
```
