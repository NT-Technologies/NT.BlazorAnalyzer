# NTBA0009: Root ErrorBoundary should consider custom ErrorContent

| Default severity | Code fix |
| --- | --- |
| Info | Yes: "Add `ErrorContent`" |

## Why it matters

When an `ErrorBoundary` has no `ErrorContent`, users see the framework's default fallback UI after a failure. Custom `ErrorContent` lets you show a clearer message and a recovery path, which matters most for root or broadly visible boundaries. This is a UX recommendation, not a framework requirement.

## What is reported

- An interactive component that opens a boundary first, in its root markup, and relies on the default fallback UI because no `ErrorContent` is set. This covers `Microsoft.AspNetCore.Components.Web.ErrorBoundary` and subclasses that do not render their own error content; custom `ErrorBoundaryBase` implementations render their own UI and are not reported.
- Reported at Info by default. Custom `ErrorContent` is optional in Blazor.

## How to fix

Before:

```razor
@rendermode InteractiveServer

<ErrorBoundary>
    <button @onclick="HandleClick">Click</button>
</ErrorBoundary>
```

After:

```razor
@rendermode InteractiveServer

<ErrorBoundary>
    <button @onclick="HandleClick">Click</button>
    <ErrorContent>
        <p>Something went wrong. Please try again.</p>
    </ErrorContent>
</ErrorBoundary>
```

The code fix inserts this exact `ErrorContent` markup. It does not render `exception.Message`, which can expose internal details to users. Edit the text to match your product.

## Configuration

None.

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0009.severity = none
```

This rule is reported on the component's markup, so use the `.editorconfig` setting above rather than a `#pragma`.
