# NTBA0004: Dispose method should use meaningful exception handling

| Default severity | Code fix |
| --- | --- |
| Warning | Yes: "Wrap body in try/catch and log" |

## Why it matters

Cleanup in `Dispose` or `DisposeAsync` runs when a component is torn down, often after the circuit has already disconnected. An exception that escapes cleanup can hide the original failure and leaves resources in an unknown state. Handling cleanup failures explicitly, and logging them, keeps teardown diagnosable.

## What is reported

- `Dispose` or `DisposeAsync` performing failure-prone cleanup with no meaningful exception handling.
- Cleanup performed by `DisposeCore`-style helpers is analyzed transitively, but the diagnostic stays on `Dispose` or `DisposeAsync`.
- Pure delegation to a safe local cleanup helper is accepted. Trivial local cleanup is not reported.
- Handling: a `catch` that does not throw contains the failure, unless it only catches cancellation (`OperationCanceledException`, `TaskCanceledException`, a `when` filter on `IsCancellationRequested`) or `JSDisconnectedException`. A `catch { throw; }`, or one that logs and rethrows, propagates the failure and does not count. Whether the catch logs is reported separately by NTBA0008, so a swallowed exception is reported once.
- JS cleanup that catches only `JSDisconnectedException` is accepted in `Dispose`/`DisposeAsync` and in `DisposeCore`/`DisposeAsyncCore` helpers when the JS call is directly inside the `try`, and in any `try` that disposes an `IJSObjectReference`, following Microsoft's documented pattern.
- Static SSR components are not reported: components with no declared render mode that have a `[CascadingParameter] HttpContext` property.

## How to fix

Before:

```razor
@implements IAsyncDisposable

@code {
    [Inject] private IJSRuntime JS { get; set; } = default!;

    public async ValueTask DisposeAsync()
    {
        await JS.InvokeVoidAsync("chart.destroy");
    }
}
```

After:

```razor
@implements IAsyncDisposable
@using Microsoft.Extensions.Logging

@code {
    [Inject] private IJSRuntime JS { get; set; } = default!;
    [Inject] private ILogger<ChartPanel> Logger { get; set; } = default!;

    public async ValueTask DisposeAsync()
    {
        try
        {
            await JS.InvokeVoidAsync("chart.destroy");
        }
        catch (Exception exception)
        {
            Logger.LogError(exception, "Chart cleanup failed.");
        }
    }
}
```

## Configuration

- Failure-prone detection: `ntba.failure_prone_type_suffixes`, `ntba.failure_prone_method_prefixes`, `ntba.safe_types`, and `ntba.failure_handling_methods`.
- Strict mode does not change this rule's severity.

See [Configuration](README.md#configuration) for the setting syntax.

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0004.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0004
// Dispose or DisposeAsync
#pragma warning restore NTBA0004
```
