# NTBA0008: Caught exceptions should report the caught exception or rethrow

| Default severity | Code fix |
| --- | --- |
| Warning | Yes: "Log exception" |

## Why it matters

A `catch` that drops the exception hides the failure: nothing is logged, and the user sees no error or a misleading result. Passing the exception object to a logger or telemetry call keeps the type, message, and stack trace available for diagnosis. Rethrowing is also acceptable because it lets the failure propagate.

## What is reported

- A general `catch` (`catch` or `catch (Exception)`) that neither passes the caught exception object to any call, nor rethrows it, nor tells the user. A catch that calls a toast or snackbar service, or stores an error message string in a field or property, surfaces the failure and is not reported; one that only resets state or returns a default is. Catching a specific exception type, such as `catch (InvalidOperationException)`, is treated as a deliberate decision and is not reported.
- Message-only use does not count. A call such as `Logger.LogError(ex.Message)` is reported because it passes the message, not the exception object.
- Accepted expected swallows:
  - catching `OperationCanceledException` or `TaskCanceledException`
  - catching `JSDisconnectedException`
  - a `when` filter that checks `IsCancellationRequested`
- Passing the exception to any call counts, including a telemetry or notification call and `await DispatchExceptionAsync(exception)`.

## How to fix

Before:

```razor
@rendermode InteractiveServer

@code {
    private void Save()
    {
        try
        {
            Repository.Save();
        }
        catch (Exception)
        {
        }
    }
}
```

After:

```razor
@rendermode InteractiveServer
@using Microsoft.Extensions.Logging

@code {
    [Inject] private ILogger<EditorPage> Logger { get; set; } = default!;

    private void Save()
    {
        try
        {
            Repository.Save();
        }
        catch (Exception exception)
        {
            Logger.LogError(exception, "Save failed.");
        }
    }
}
```

The code fix inserts the `LogError` call and names the exception variable when it is not already named.

## Configuration

None.

## Suppressing

In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.NTBA0008.severity = none
```

In code:

```csharp
#pragma warning disable NTBA0008
// catch block
#pragma warning restore NTBA0008
```
